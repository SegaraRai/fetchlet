# Solid + axum

Serves a Solid 2 application from axum: streaming SSR, a `query` server
function, API routes and file routes, built with `@solidjs/vite-plugin` in
server mode and without SolidStart.
[fetchlet/solid](../../packages/fetchlet/docs/solid.md) builds the server
into an artifact.

## Run

From the repository root:

```bash
vp install --frozen-lockfile
vp run @fetchlet-internal/example-solid-axum#serve
```

Open `http://127.0.0.1:3610`. The task builds, then starts the server on
QuickJS.

## Layout

| Path                   | Role                                                                      |
| ---------------------- | ------------------------------------------------------------------------- |
| `src/App.tsx`          | The router shell and navigation                                           |
| `src/Document.tsx`     | The HTML document Solid renders around the app                            |
| `src/routes/`          | Pages, API routes (`src/routes/api/`) and the 404 route                   |
| `src/middleware.ts`    | Serves the API routes ahead of page rendering                             |
| `src/lib/completed.ts` | State shared between API route handlers                                   |
| `vite.config.ts`       | Solid, file routes and fetchlet Vite plugins, Vite+ tasks                 |
| `src/*.rs`             | Starting axum, bindings, routing                                          |
| `config.json`          | Listen address, queue, body budgets, deadline, background budgets, stacks |
| `tests/e2e.test.ts`    | Checks over real HTTP in a real browser                                   |
| `build/`               | `server.js`, `client/`, `assets.flpk`, `fetchlet.json`                    |

Server functions and API routes read the bindings, the client address and
`waitUntil` with `getRequestContext()` from `fetchlet/solid/context`;
`src/global.d.ts` types the bindings. `file-routes.d.ts` is generated by
`filesystem-routing` during the build.

`quickjs_stack_bytes` (4 MiB) and `worker_stack_bytes` (8 MiB) in
`config.json` match the [SolidStart example](../solidstart-axum/README.md);
the minimum this framework needs has not been measured.

## Checks

```bash
vp run setup:browser
vp run test:examples -- solid-axum
```

The shared checks (`tools/examples/common-checks.ts`) cover SSR and
escaping, the Rust service binding, assets, JSON endpoints, client address
and bindings, the axum route, body budgets, streaming uploads, `waitUntil`,
concurrent requests, hydration, client navigation and streaming. Results go
to `results/example-solid-axum.json`.
